Build Your Own Skills

One command for a task you repeat, with the same result every time.

Duration: half a day · Builds on: Memory · Integrations

A skill is a short written instruction your AI follows step by step: what goes in, what it does, what comes out. You write it once, and you stop explaining the same task every week.

You leave with

  • One skill for a task you or your team repeat every week, written as a short file: input, steps, output.
  • One command that runs it, tested on three real inputs from your own work.
  • A short list of what the skill must never do, written into the skill itself.
  • The spec for a second skill, ready for next time.

Ideas to try

  • A hair salon has a skill that turns tomorrow's bookings into a reminder text per client, in the salon's own tone.
  • A plumber types one command after a job and gets a draft invoice line from the work order: hours, parts, VAT.
  • A bookkeeping office runs one skill on a client's bank export that lists the lines it cannot categorize, instead of guessing them.
  • A small hotel answers a booking request with a skill that picks the room, the price and the cancellation terms from its own rate sheet.
  • A freelance translator runs one skill on every new job that checks word count, deadline and rate before saying yes.

Your turn

Which task do you explain again every few weeks, to a new colleague or to your AI? Bring three real examples of it.

What we do in the session

  1. 20 min — Pick one task. Write down what goes in and what a correct result looks like.
  2. 40 min — Write the skill as a spec: input, steps, output, and what it must not do.
  3. 40 min — Run it on three real inputs. Compare each result with what you would have made by hand.
  4. 30 min — Fix the spec where the result was wrong, and run the same three inputs again.
  5. 20 min — Give it a command name and one line on when to use it, so a colleague can run it too.

What you bring

  • A laptop and three to five real examples of the task: the input, and the result you made by hand.
  • The steps you follow now, even if they only live in your head.

Tools

Claude Code to write and run the skill; any text editor. Optional: the same instruction saved in a chat project, for colleagues who do not use a terminal.

Example from my own system

One of my skills takes an export of my AI chats and files every conversation in the folder of the day it happened. It filed 638 ChatGPT conversations and 9 Claude conversations, and the next export goes through the same command with the same result. Before the skill, I would have typed the same instructions every time. Routing phone scans works the same way, as a written runbook the AI follows: see From phone scan to the right folder, named and indexed.

Pitfalls

  • Testing on the example you wrote it from. It will pass. Test on input the skill has not seen.
  • One skill that does five things. One command, one result. Chain two skills later if you need both.
  • No idea what a correct result is. If you cannot say it, you cannot test the skill, and you will not notice when it starts to drift.

Works best after

Build Your Own Memory gives the skill something to read. Build Your Own Integrations gives it access to the system where the task lives, such as your mail or your bookkeeping.

Concepts behind it

  • Reusable Skills — Reusable, AI-readable units of behavior — a skill packages how to do one thing well, versioned and callable, so people and AI apply it the same way every time.
  • Write the Spec, Not the Prompt — A prompt is a request you repeat. A spec is a contract the work is checked against — and it is the artefact that survives the session.
  • Runbooks — A repeatable procedure written down so a task is done the same way every time.
  • Evals Are the Release Gate — An eval suite that doesn't block a release isn't a gate, it's a report. No evals, no ship.
