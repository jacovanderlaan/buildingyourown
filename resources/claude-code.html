Claude Code

The AI coding tool most of the use cases on this site were built with. Strong when it gets a spec, rules and a way to check its own work.

Anthropic

What it is

Claude Code is Anthropic's coding agent. It runs in the terminal, in your editor or in the desktop app, reads the files in your project, writes and runs code, and checks the result. You describe what a tool must do; it does most of the typing.

How I use it

Almost every use case on this site was built with it. What makes the difference is not the prompt but what surrounds it:

  • A CLAUDE.md file in every project, with the conventions, the folder layout and the lessons from earlier mistakes. It loads at the start of every session, so the agent does not start from zero.
  • Rules that load by path, so a warning about one folder only appears when that folder is touched.
  • Hooks that run a check automatically, instead of hoping the agent remembers to.
  • Skills for work that repeats, such as building a site or importing a data export.

On a Build Day

You work in your own account, on your own example data. The day teaches the habits that keep the speed and drop the hangover: a short spec before the first line of code, a test the tool must pass, and one file where every correction is written down.

Watch out

It is very good at sounding right. Ask it to prove a result (count the rows, open the page) instead of accepting "done".

Concepts behind it

  • CLAUDE.md as Operating System — Standing rules the AI reads before it acts — a layered OS for how the assistant behaves in your world.
  • Write the Spec, Not the Prompt — A prompt is a request you repeat. A spec is a contract the work is checked against — and it is the artefact that survives the session.
  • Hooks Over Hopes — Every instruction to a model is a probability, not a promise. Rules that must always run belong in deterministic automation the model can't skip.
  • The Mistakes File — Same mistake twice = a new rule. Corrections you'd otherwise repeat forever get written into a file the AI reads every run.
  • Reusable Skills — Reusable, AI-readable units of behavior — a skill packages how to do one thing well, versioned and callable, so people and AI apply it the same way every time.
  • Evals Are the Release Gate — An eval suite that doesn't block a release isn't a gate, it's a report. No evals, no ship.
