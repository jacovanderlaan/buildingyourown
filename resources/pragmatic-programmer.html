What the book is about

David Thomas and Andrew Hunt's classic on the craft of programming, updated in 2019. Short, practical tips: tracer bullets, small steps, plain text, automation, and taking responsibility for your work.

Ideas I took from it

  • Don't repeat yourself is about knowledge, not code. Every fact should have one authoritative place; everything else is derived from it.
  • Write code that writes code. Repetitive work is a job for a generator, which is exactly what AI now is.
  • Keep knowledge in plain text. It outlives every proprietary format.

On a Build Day

With AI typing, these habits matter more, not less: one source for every rule, small steps you can check, and plain files you own.

Concepts behind it

  • Metadata First — Metadata is the material Breakthrough Modeling is built from — structure, logic and meaning captured as data, so the platform and the AI can both read and run it.
  • Write the Spec, Not the Prompt — A prompt is a request you repeat. A spec is a contract the work is checked against — and it is the artefact that survives the session.
  • Reusable Skills — Reusable, AI-readable units of behavior — a skill packages how to do one thing well, versioned and callable, so people and AI apply it the same way every time.
