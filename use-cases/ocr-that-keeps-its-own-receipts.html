Document management

Document intake that keeps its own receipts

Feeding thousands of documents into a document system, with a ledger that proves what arrived, avoids duplicates, and re-reads the badly recognised ones.

Replaces
trusting a document system's import blindly
Built with
open-source document system (Paperless-ngx) on a home server, Python, DuckDB, an OCR service
In numbers
15,455 PDFs pushed · 33% duplicates avoided · 8,509 of 8,630 re-read

The situation

Document systems promise to make everything searchable. In practice imports fail silently, the same file goes in three times, and old receipts come out as gibberish.

What I built

  • An intake ledger: every file is identified by a fingerprint of its content (SHA-256). A document counts as arrived only after the system confirms it.
  • Duplicates never go in twice — a third of the files turned out to be copies.
  • A re-read pipeline: badly recognised documents are rendered as images and read again by a better OCR service; the improved text is written back.

What went wrong

A faded restaurant receipt came out with the wrong name. The OCR service quietly reused the existing text layer of the PDF. Sending it images instead of the PDF fixed it — one of those details you only learn by checking.

The structure underneath

Never trust exit code 0. Count what arrived.

Start on a Build Day

Bring fifty documents. Build the ledger first, the search second.

Concepts behind it

  • Never Marks Its Own Homework — The judge must be separate from the builder, and the score is the off-switch: a loop only stops when an independent evaluator says the rubric is met.
  • Reality Check — Test the model and the plan against the real world — the actual data, deliveries and behavior — not against the assumption you started with.
