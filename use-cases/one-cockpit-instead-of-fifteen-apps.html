The rest of the business OS

One cockpit instead of fifteen apps

Actions, ideas, incidents, finance, documents and photos — all as files with status fields, all readable in one app on the phone.

Replaces
a dashboard per tool
Built with
one Python server without frameworks, one HTML file, about 49 DuckDB databases
In numbers
699 tracked items · 16 cockpits in one app

The situation

Every tool brings its own dashboard. Nobody looks at fifteen dashboards.

What I built

Every action, idea and incident is a small file with a status field. A script collects them into one table; one app shows them — next to finance, receipts, documents, photos and trips — on my phone. The app has no build step and no framework: one server file and one page.

The structure underneath

When the data has one shape, the cockpit is cheap. AI generated most of the screens; the work was in the structure.

Honest note

It is built for one person. It has no login of its own and relies on a private network. A company version needs authentication first.

Start on a Build Day

Bring the three lists you check every week. Give them one shape, and build one page that shows all three.

Try it on a Build Day: A cockpit for the three lists you check every week

Concepts behind it

  • Eat Your Own Dogfood — Use your own tool/method on your own real work before and while you ask anyone else to — dogfooding surfaces the flaws a demo hides.
  • Deliberate Simplicity — Make each part as plain as it can be without losing what matters — reuse only the fraction you actually need, and strip the rest.
