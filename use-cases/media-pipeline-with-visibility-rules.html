Digital asset management

A photo pipeline that knows what is private

Every new photo is filed by day and activity, gets a metadata file, and is classified private, shared or never-share by rules on its folder — before anything leaves the house.

Replaces
cloud photo sync with one setting for everything
Built with
Python pipeline, folder notes, encrypted network storage
In numbers
206,092 files tracked · runs daily at 07:30

The situation

Cloud photo services have one switch: everything goes up, or nothing does. Real life has more categories.

What I built

A daily pipeline: new photos land in an inbox, are filed into day and activity folders, get a sidecar, and are classified by rules written on the folder: private, shared, needs review, never. Only then are they pushed to network storage, where viewers read them. Dry-run is the default everywhere; 35 tests guard the rules.

What went wrong

Days with subfolders were skipped, so a quarter of one day's photos got no sidecar. A count, not a feeling, found it.

The structure underneath

Visibility is data on the folder, decided once, applied every time.

Start on a Build Day

For a company: the same pipeline sorts project photos, site inspections or product shots, and decides which may go on the website.

Concepts behind it

  • Deterministic by Design — Deliberate is whether the structure was chosen; deterministic is whether the output repeats. A toy is neither on the second try.
  • Rules You Can Verify — '2-space indent' is a rule; 'format code properly' is a wish. A rule the system can't check is decoration.
