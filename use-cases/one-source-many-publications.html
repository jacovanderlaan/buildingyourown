One source, three publications: birthdays

A small case with a big principle: one file is the source, and the calendar, the contact list and a web page are publications generated from it.

Replaces
a birthday-reminder service and a calendar used as a database
Built with
one YAML file, three small publishing scripts
In numbers
130 people merged from 5 sources

The situation

Birthdays were spread over five places: a reminder service, a phone, a calendar, a family list and memory. Seventeen of them existed in only one place.

What I built

One YAML file is the only place where a birthday is written. Scripts publish it to the contact list (which fills the phone's birthday calendar), to a calendar file and to a page. Every script runs dry first, only updates, and never silently overwrites a conflict.

The structure underneath

Publishing is one-way. Fix the source, republish everywhere. The same pattern works for price lists, product data, opening hours and staff lists.

Start on a Build Day

Pick one list your company keeps in three places. Make one file the source and generate the other two.
